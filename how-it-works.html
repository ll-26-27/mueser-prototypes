How it works

The desktop app is where you ask for work. Your folder holds the material and the results. These pages are where you inspect what happened.

One folder, several ways to work

The desktop app operates the project tools. Those tools read your folder and produce pages or documents to review. Model calls are shown outside the local workspace.

Workflow diagram · available offline
  1. Give the desktop app a task and access to the relevant project folder. Its coding agent can run the project’s scripts; the same commands can also be run in a terminal.
  2. Scripts read source files, do local processing, and call a model or reference service only at the steps that need one. Results are written into the project folder.
  3. Open the resulting page or document. Review doubtful readings, proposed connections or suggested changes.
  4. For the implemented review pages, a local server saves actions to the log. Applying decisions or rebuilding produces the next output.

Two kinds of model work

The app’s model interprets your request and helps operate the tools. It receives the conversation and whatever file context the desktop app supplies.

The scripts’ task models perform specific passes, such as transcription or translation. Those calls use the repository’s API configuration and keep their prompts and replies with the run evidence.

Local files, explicit calls

Keeping a project in a local folder does not mean every model runs locally. Context sent by a desktop app or an API step goes to the model service configured for that step.

Opening a generated page does not itself run the transcription or translation models. The timeline can load linked portraits online; maps can request online map tiles.

A folder you can inspect

Each project keeps the material, the operations and the outputs together. Runs record how a result was produced; the review log records your decisions.

project/
  inputs/       source files and settings
  operations/   commands for each step
  outputs/      pages, documents and run folders
    log…        review decisions, by project
Saving from a page. Start that project’s local server to save review actions to disk. When opened directly as a file, a review page keeps work in the browser and offers an export to import into the project. A static website cannot write directly into your folder.
